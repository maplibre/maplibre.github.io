## MapLibre Native

### Cross-platform Plugin System

An update on the new cross-platform plugin system for MapLibre Native. A first version of the [C API](https://github.com/maplibre/maplibre-native/blob/ba9fc57bc88725d7602fd652e601384e9f2e3183/include/mln/plugin/plugin_api.h) has landed this month! We also already saw various PRs ([#4654](https://github.com/maplibre/maplibre-native/pull/4654), [#4692](https://github.com/maplibre/maplibre-native/pull/4692), [#4665](https://github.com/maplibre/maplibre-native/pull/4665)) that extended the capabilities of the plugin system. This is exactly the approach that we want to take: gradually expand the scope of the plugin system to make sure it fits all the use cases that our users have.

It should be noted that during this development phase the plugin system is not stable yet. Regular builds also do not include it yet (all intergration code is guarded with a `MLN_WITH_PLUGINS` build flag). However, for those that want to experiment with the plugin API already, we did put out a pre-release for MapLibre Android that includes it. Please see [this repository](https://github.com/louwers/maplibre-native-plugin-android-example) for an example. MapLibre iOS will follow suit.

Note that these plugins tie directly into the core. The plugins are _cross-platform_, and thanks to the C API, once the API is stable, people will be able to publish plugins that will continue working across versions. We believe that this has the potential to create a true plugin ecosystem for MapLibre Native. By having a powerful plugin system, we allow people to extend the library and experiment, while keeping the core library stable (and small). Below you can find a small taste of some interesting ideas.

### OpenHarmony Platform

With [#4315](https://github.com/maplibre/maplibre-native/pull/4315) merged we now have a new platform: [OpenHarmony](https://en.wikipedia.org/wiki/OpenHarmony). OpenHarmony has about 20% smartphone market share in [China](https://www.idc.com/resource-center/blog/china-smartphone-market-decline-q2-2026) and about 5% [globally](https://counterpointresearch.com/en/insights/global-smartphone-os-market-share). What makes this platform interesting as well is [Oniro](https://oniroproject.org/). This is an Eclipse Foundation Project that builds on OpenHarmony and is "dedicated to the development of an open source vendor-neutral Operating System (OS) platform".

### Call for MapLibre Accessibility Features

Tim Sylvester implemented the ability to introspect rendered features in [#4460](https://github.com/maplibre/maplibre-native/pull/4460) this month. While this functionality was built primarily with testing purposes in mind, it might offer some opportunities for MapLibre Native to better intergrate with accessibility tools such as screen readers. We would be very eager to hear from people willing to [share](https://github.com/maplibre/maplibre-native/discussions/3439) their ideas on how to push such accessibility efforts.
