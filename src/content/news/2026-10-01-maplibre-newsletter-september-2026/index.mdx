## MapLibre Native

### Cross-platform Plugin System

An update on the new cross-platform plugin system for MapLibre Native.

<Announcement>
  🚀 A first version of the [C
  API](https://github.com/maplibre/maplibre-native/blob/ba9fc57bc88725d7602fd652e601384e9f2e3183/include/mln/plugin/plugin_api.h)
  has landed this month!
</Announcement>
We also already saw various PRs
([#4654](https://github.com/maplibre/maplibre-native/pull/4654),
[#4692](https://github.com/maplibre/maplibre-native/pull/4692),
[#4665](https://github.com/maplibre/maplibre-native/pull/4665)) that extended
the capabilities of the plugin system. This is exactly the approach that we want
to take: gradually expand the scope of the plugin system to make sure it fits
all the use cases that our users have.

It should be noted that during this development phase the plugin system is not stable yet. Regular builds also do not include it yet (all integration code is guarded with a `MLN_WITH_PLUGINS` build flag). However, for those that want to experiment with the plugin API already, we did put out a pre-release for MapLibre Android that includes it. Please see [this repository](https://github.com/louwers/maplibre-native-plugin-android-example) for an example. MapLibre iOS will follow suit.

Note that these plugins tie directly into the core. The plugins are _cross-platform_, and thanks to the C API, once the API is stable, people will be able to publish plugins that will continue working across versions. We believe that this has the potential to create a true plugin ecosystem for MapLibre Native. By having a powerful plugin system, we allow people to extend the library and experiment, while keeping the core library stable (and small). Below you can find a small taste of some interesting ideas.

## 🦀 Martin

<Announcement>
  Martin 2.0 is now officially in beta! Test it against your setup and check out
  our new migration guide.
</Announcement>

We released 3 versions this month: [1.16.0](https://github.com/maplibre/martin/releases/tag/martin-v1.16.0), [1.16.1](https://github.com/maplibre/martin/releases/tag/martin-v1.16.1) and the first beta of [Martin 2.0 (2.0.0-beta.0)](https://github.com/maplibre/martin/releases/tag/martin-v2.0.0-beta.0).
We merged more than 150 non-bot PRs, and **Martin 2.0 is now in beta**.
Please try the beta against your setup and [tell us](https://github.com/maplibre/martin/issues) what breaks.
We have written a [migration guide](https://maplibre.org/martin/migration-guide/):
2.0 removes the options that v1.x and v0.x deprecated, changes some defaults and needs PostGIS 3.5 or newer.
If Martin 1.16 starts without deprecation warnings for you, you're probably fine (the only un-warned change is `martin-cp` -> `martin cp`).

Here are some highlights:

- **Tile grids other than Web Mercator**: PostgreSQL, MBTiles and PMTiles sources can now be served
  on other grids, such as national or polar ones. Seven grids from the OGC registry are built in
  (for example `NZTM2000Quad`), and you can define your own in the config.
- **Server-side rendering is stable**: It is no longer experimental. It has moved out of the
  default build into the `-full` Docker images and tarballs due to having some shared library version dependencies.
- **Faster startup**: Martin accepts connections while its sources are still loading, and PostgreSQL discovery does less work per table. `/health` still only reports ready once everything has loaded.
- **Aliases** for fonts, sprites and tile sources: give a font fallback stack, a sprite set or a
  set of tile sources one name, and a style can request it like a single source.
- **CQL2 filters on table sources**: write `filter: population > 100000` on a table instead of
  writing a SQL function.
- **A terminal dashboard** shows sources, request rates, a live world map of tile requests and the log. In 2.0 it is on by default in an interactive terminal (`--no-tui` turns it off).
- `martin-cp` is now the `martin cp` subcommand. It can skip now also skip tiles below an empty tile, which took a world copy from 243s down to 11s on our test database.
- Performance work on the tile cache: on a warm cache, serving a tile's content dropped from
  107µs to 29µs.
- Unstable (feature-gated) work continued on DuckDB/GeoParquet sources (`s3://`, `hf://` and
  more, `.duckdb` files, hot reload) and on remote COG sources.

As always, we would like to thank all the contributors this month, this wouldn't have been
possible without your help!

## MapLibre Tiles (MLT)

<Announcement>
  📦 Announcement: MLT v2 has evolved from a spec skeleton into a fully working
  format complete with its own high-performance Rust encoder/decoder, docs, and
  interactive inspector.
</Announcement>

This month was about [MLT v2](https://github.com/maplibre/maplibre-tile-spec). It went from a header and metadata skeleton to a working format with its own encoder, decoder, docs and inspector. Everything MLTv2 is still behind the `unstable-v2` feature while there are still unresolved questions (see below).

We shipped [13 releases of mlt-core (0.12.7 -> 0.16.0)](https://crates.io/crates/mlt-core), along with the mlt CLI, the FFI, WASM and Python bindings, and @maplibre/mlt 1.2.1 and 1.3.0.

Here are some highlights, although there are too many to list:

- Every column kind now round-trips in v2. That covers strings, floats, nested properties and m-values. Nested properties use an ORC-style node tree, and a nested node's structure is written once per row instead of once per entry. That saves 13.6% on a group of name\* columns and 9.8% on a bag of all properties.
- Strings. Dictionaries are front-coded, and a layer can share one dictionary across columns. Together that cuts the whole tile by 18.3% on OpenMapTiles and 21.5% on the tiles that one of our sponsors Amazon provided.
- Floats. A float column can be stored as a dictionary or with ALP, which is chosen only when every value comes back bit for bit. ALP stores a frame of reference, races FastPFOR against varint for its offsets, and packs its two parameters into a single byte. This cuts decimal columns by 19.5% and makes the parameter search about 10x faster.
- Smaller headers.
  - The extent fits in a nibble.
  - The column and m-value counts share one variant.
  - Raw streams with a fixed element width no longer store their byte length.
  - The spare nibble in the layer header now holds the geometry type when a layer has only one. About 60% of layers are like this and no longer write a types stream.
- Geometry. Dictionary and tessellated layouts have been merged. A layer made only of tessellated polygons stores can store just its triangles, and triangle indices count from the layer's first vertex instead of relatively to the start.
- Presence and dictionary codes. Dictionary children share their parent's presence bitfield, presence can be run-length encoded again (up to 4% smaller), and dictionary codes are bit-packed when that beats one varint per code.
- Tile inspector. The new inspector is built on our WASM bindings to the high performance rust encoder/decoder. It shows a hex view of the tile next to a tree of its regions, draws the geometry, loads tiles from a URL, and has filters with live counts. Check it out -> https://maplibre.org/maplibre-tile-spec/inspector/
- We have also rewritten most of our docs and it should be much more approachable. If something is unclear, that is a bug and we would love your questions.
- We have also done a bunch of Hardening.
  - Malformed FSST data, oversized dictionary child counts, vertex index overflow and float encodings that don't fit are now rejected instead of panicking.
  - Polygon rings with no area are skipped during tessellation.
  - Tests moved to cargo-nextest, with a big push on coverage of the error paths in the codecs.
- Cleanup. We removed the Pseudodecimal encoding, which was never implemented, the Java encoding server, the (currently sadly unmaintained) C++ encoder from CI.

## 🎨 MapLibre Compose

Over the past couple of months, MapLibre Compose has shipped a shared implementation for Android, iOS, and desktop built on [MapLibre Native FFI](https://github.com/maplibre/maplibre-native-ffi). These releases closed nearly all the previously open issues (about 80!), completed feature parity work for desktop and web, including map styling and proper compositing with Compose UI, added long-requested features including a [map snapshotter and imperative styling APIs](https://github.com/maplibre/maplibre-compose/releases/tag/v0.16.0), plus support and demos for integrating maps with [Android Auto](https://github.com/maplibre/maplibre-compose/pull/1301) and [CarPlay](https://github.com/maplibre/maplibre-compose/releases/tag/v0.17.0).

[StreetComplete](https://github.com/streetcomplete/StreetComplete), the OpenStreetMap surveying app, has also [merged its migration](https://github.com/streetcomplete/StreetComplete/pull/7088) from direct MapLibre Native Android integration to MapLibre Compose, sharing its map implementation across Android and iOS.

MapLibre Compose is now essentially feature-complete, except for Kotlin Wasm support which is in draft until the next Compose Multiplatform release. The remaining work before 1.0 is improving documentation, performance, finding and squashing bugs, and improving API ergonomics. User feedback is especially important at this stage.
